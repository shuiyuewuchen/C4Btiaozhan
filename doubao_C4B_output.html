为什么你需要一条内容流水线

先问一个问题：你上一次写公众号文章，花了多长时间？

我的第一反应是：写内容大概 1 小时，但排版、调格式、折腾样式，又花了 1 小时。内容只占一半时间，另一半全在跟编辑器搏斗。

💬 在 AI 时代，真正稀缺的不是写作能力，而是"把想法变成成品"的效率。

如果你每周写一篇文章，排版时间加起来就是每年 100 多个小时。这些时间用来写更多内容、陪家人、或者休息不好吗？

所以我做了一个决定：把排版这件事彻底自动化。

流水线长什么样

理想的内容流水线是这样的：

  1. 用 Markdown 写文章（随便什么编辑器，Typora、VS Code、备忘录都行）
  2. 运行一条命令，自动完成格式转换和排版
  3. 浏览器预览，确认效果
  4. 复制粘贴到公众号后台，发布

就这四步。没有中间的折腾。

关键在于第 2 步——那个"一条命令"背后的转换工具。它需要懂公众号编辑器的所有"潜规则"。

公众号编辑器的五个坑

如果你自己手动排过版，一定踩过这些坑：

坑 表现 后果
不支持 class 你写了 CSS 类名，保存后全没了 样式丢失
不支持 h1 h1 被强制降级或忽略 标题层级混乱
不支持 div div 标签直接被删 布局崩塌
SVG 图片消失 保存后矢量图变成空白 图片丢失
代码块乱掉 pre/code 标签被剥离 代码全挤成一行

⚠️ 这些坑最烦人的地方在于：你在浏览器里预览是好的，一旦粘贴到公众号再保存，格式就"神秘消失"了。这是因为公众号后台会过滤掉它不认识的标签和样式。

解决办法只有一个：所有样式必须写成 inline CSS，所有标签必须用公众号允许的那几个。

但手动给每个标签加 inline style？那比排版还累。

我做了什么

我从一个开源的 starter kit 出发，用 AI 辅助，把它改造成了自己的"公众号发布技能"。具体加了这些能力：

第一，五套配色主题。 不同类型的文章配不同的风格——技术文章用商务蓝，生活随笔用暖橙风，读书分享用森系绿。一条 --theme blue 命令切换。

第二，Callout 高亮框。 写 > [!NOTE] 就能生成一个蓝色提示框，写 > [!WARNING] 就是黄色警告框。这是公众号文章里最常见的排版元素，以前要手动加 HTML，现在写 Markdown 就行。

第三，自动目录。 文章超过 3 个标题，自动在开头生成一个目录卡片。长文读者不用翻半天找小节。

第四，中文排版优化。 中英文之间自动加空格。这种细节手动调能烦死，但读者会觉得"这篇文章很专业"。

第五，文章元数据和页脚。 frontmatter 里写好标题、作者、摘要，自动渲染成文章头部。结尾自动加分隔线和版权声明。

实际效果

用这个流水线写这篇文章的时间分配：

  • 构思大纲：5 分钟
  • AI 辅助写初稿：10 分钟
  • 修改润色：10 分钟
  • 运行转换命令：10 秒
  • 浏览器预览确认：2 分钟
  • 粘贴到公众号后台：1 分钟

总计不到 30 分钟。 而以前光排版就要半小时以上。

💡 效率提升的关键不是"写得更快"，而是"消除了所有不必要的摩擦"。排版、格式、样式——这些事跟写作本身无关，但它们消耗了你最多的意志力。

这个思路可以迁移

内容流水线的本质是：把重复的、有规律的、不创造核心价值的环节，全部工具化。

这个思路不只适用于公众号：

  • 写知乎回答？Markdown 转知乎格式
  • 做技术文档？Markdown 转 PDF 或网页
  • 写邮件？模板 + 自动填充
  • 做周报？从日历和任务自动汇总

📘 问自己一个问题：你每周花最多时间做的、最不想做的那件事，能不能打包成一个"输入 X → 输出 Y"的工具？

如果答案是"能"，那你就找到了下一个值得自动化的环节。

写在最后

工具会不断进化，但"把想法变成成品"这个能力永远稀缺。

流水线不是为了让你写得更少，而是为了让你把省下来的时间，用在更有价值的思考上。毕竟，读者关心的是你说了什么，不是你的段落边距是 12px 还是 14px。

先跑起来，再迭代完美。
